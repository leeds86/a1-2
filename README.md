# 🗺️ AI 기반 국내 여행 추천 및 맛집 가이드 프로그램

Gemini AI(LLM)와 카카오맵 API를 활용하여, 입력한 날짜에 가기 좋은 국내 여행지를 추천하고 지역별 맛집 리스트를 포함한 깔끔한 여행 리포트를 자동 생성하는 프로그램입니다.

## ✨ 주요 기능
* **복수 지역 추천:** 1개의 지역이 아닌 2~3개의 맞춤형 여행지를 추천합니다.
* **지역별 맛집 검색:** 카카오맵 API를 활용해 추천된 지역의 실제 맛집 정보와 지도 링크를 제공합니다.
* **결과 캐싱 (최적화):** 동일한 날짜로 다시 실행할 경우, 불필요한 API 비용을 아끼기 위해 이전에 검색한 데이터를 재활용합니다.
* **자동 리포트 생성:** 생성된 정보들을 모아 보기 좋은 마크다운(.md) 형식의 문서로 자동 저장합니다.

## 🚀 실행 방법 (가상 환경 사용)

최신 파이썬 환경에서는 시스템 충돌 방지를 위해 '가상 환경(나만의 작업 공간)'에서 실행하는 것을 권장합니다.

### 1. 프로젝트 다운로드 (Clone)
먼저 깃허브에서 프로젝트 코드를 다운로드하고, 작업할 폴더로 이동합니다.
```bash
git clone https://github.com/본인깃허브계정/a1-2.git
cd a1-2/travel_planner
```

### 2. 패키지 설치 (최초 1회만)
터미널(명령 프롬프트)을 열고 아래 명령어를 입력하여 필요한 도구들을 설치합니다.
(최신 파이썬 환경의 보안 경고를 우회하여 강제 설치하는 명령어입니다.)
```bash
pip install -r requirements.txt --break-system-packages
```

### 3. 프로그램 실행
아래 명령어로 프로그램을 실행합니다.
```bash
python travel_planner.py --date 2026-10-10
```
*(날짜는 `YYYY-MM-DD` 형식으로 자유롭게 변경 가능합니다.)*

## 🔑 API 키 설정 방법 (.env)

이 프로그램이 정상적으로 작동하려면 구글 제미나이(Gemini)와 카카오(Kakao)의 API 키가 필요합니다.  
초보자도 쉽게 설정할 수 있도록 템플릿 파일(`.env.example`)을 함께 제공합니다.

1. 프로젝트 폴더에 있는 **`.env.example`** 파일의 이름을 **`.env`** 로 변경합니다. (파일명 앞에 점(.)이 있어야 합니다.)
3. 변경한 `.env` 파일을 열고, 아래와 같이 발급받은 키를 붙여넣고 저장합니다.

```env
# .env 파일 작성 예시
GEMINI_API_KEY=your_gemini_api_key_here(실제 발급받은 제미나이 키)
KAKAO_API_KEY=your_kakao_api_key_here(실제 발급받은 카카오 키)
```

### 🚨 [매우 중요] API 키 유출 주의!
* API 키는 본인의 지갑 비밀번호와 같습니다. 유출될 경우 타인이 무단으로 사용하여 **요금 폭탄**을 맞거나 계정이 정지될 수 있습니다.
* 코드를 **GitHub, 블로그, 외부 커뮤니티 등에 업로드할 때 절대 `.env` 파일을 함께 올리지 마세요.**
* GitHub을 사용하신다면 반드시 `.gitignore` 파일에 `.env`를 추가하여 업로드를 원천 차단하시기 바랍니다.

## 📂 결과물 확인 방법

프로그램이 성공적으로 실행을 마치면, 코드가 있는 위치에 **`results`** 라는 폴더가 새로 생깁니다.

* **`report_YYYY-MM-DD.md` (여행 리포트)** 
  * 완성된 최종 여행 리포트입니다. 
  * 마크다운(.md) 파일을 지원하는 뷰어나 Notion(노션) 등에 붙여넣기 하시면 맛집 카카오맵 링크까지 깔끔하게 클릭할 수 있는 형태로 확인할 수 있습니다.
* **`data_YYYY-MM-DD.json` (원본 데이터)**
  * AI와 카카오맵에서 받아온 원본 데이터입니다. 
  * 이 파일이 있으면 다음 번에 동일한 날짜로 실행할 때 외부 API를 호출하지 않고 빠르게 리포트만 다시 만들어냅니다.

## 🧠 개발 및 설계 노트

본 프로젝트는 API 연동 및 데이터 파이프라인 구축의 핵심 원칙을 준수하여 설계되었습니다.

### 1. 코드 구조 및 모듈화 (Architecture)
* **관심사 분리(SoC):** 프로그램의 핵심 흐름을 3단계로 완벽히 분리하여 캡슐화했습니다.
  1. `get_recommendations()`: LLM을 통한 데이터 생성
  2. `search_restaurants()`: 외부 지도 API를 통한 장소 검색
  3. `generate_report()`: 수집된 데이터를 바탕으로 최종 Markdown 문서 렌더링
* **확장성을 고려한 추상화 및 인터페이스:** 지도 검색 로직이 메인 흐름과 강하게 결합되지 않도록 독립된 함수(`search_restaurants`)로 추상화하여 플러그인(Plug-in)처럼 동작하게 만들었습니다. 향후 Kakao API에서 Naver API로 제공자를 변경하더라도, 메인 로직은 전혀 건드릴 필요 없이 해당 함수 내부의 통신 규격(URL, Header)만 교체하면 되는 유연한 구조입니다.

### 2. 데이터 파이프라인 및 스키마 검증 (Data Pipeline & Validation)
* **JSON 형식 강제 이유:** LLM의 자유 텍스트(자연어) 응답은 기계적인 후속 처리가 불가능합니다. 프롬프트 단계부터 엄격한 JSON 형태를 강제하여, AI의 창작물을 다음 단계(지도 검색 API)의 검색 키워드로 즉시 연결할 수 있는 '자동화된 파이프라인'을 구축했습니다.
* **1차 JSON 스키마 필수 키 검증:** LLM 응답 직후, 4개의 필수 키(`recommended_cities`, `weather`, `events`, `reason`) 존재 여부를 `in` 연산자로 검증합니다.
* **타입 방어 및 흐름 유지:** 키가 누락되었을 경우 프로그램이 중단(Crash)되지 않도록 기본값(`[]` 또는 `"데이터 없음"`)을 주입하여 런타임 에러(TypeError 등)를 방어합니다.

### 3. API 네트워크 설계 및 보안 (Network & Security)
* **GET/POST 선택 근거:**
  * **GET (카카오 API):** 서버의 기존 장소 데이터를 단순 '조회(Read)'하므로 URL 파라미터를 활용하는 GET 방식을 사용했습니다.
  * **POST (Gemini API):** 긴 프롬프트와 문맥을 전달하여 새로운 텍스트 데이터를 '생성(Create)'해야 하므로 페이로드가 큰 POST 방식을 채택했습니다.
* **보안 및 환경변수(.env) 관리:** API 키가 하드코딩되어 외부에 노출될 경우 금전적 피해 및 계정 탈취 위험이 있습니다. 이를 방지하기 위해 `python-dotenv`를 활용하여 안전하게 분리했습니다.
* **401/403 에러 디버깅 순서:** 인증/권한 에러(401/403) 발생 시 다음 순서로 디버깅을 수행하도록 체계를 잡았습니다.
  1. `.env` 파일 내 API 키의 오타 및 로드 누락 여부 확인
  2. 제공자(Kakao/Google) 개발자 콘솔에서 해당 서비스(로컬 API 등) 활성화 여부 확인
  3. 일일 무료 호출 한도(Quota) 초과 여부 확인
  
### 4. 심화 예외 처리 및 성능 최적화 (Exception Handling & Optimization)
* **불완전 JSON 파싱 방어 및 재시도:** LLM이 마크다운(```json)을 섞어 출력하는 오작동에 대비해 정규표현식(`re.search`)으로 순수 데이터만 추출합니다. 실패 시 프롬프트 제약 조건을 강화하여 최대 2회 재시도(Retry)하는 로직을 구현했습니다.
* **오류 누적(errors) 및 사용자 경험:** 
  * 검색 결과가 0건이거나 네트워크 오류가 발생해도 로직을 중단하지 않고 빈 리스트(`[]`)를 반환합니다.
  * 발생한 모든 에러는 `errors` 리스트에 누적되어 최종 리포트 하단 '오류 요약'에 기록되므로, 사용자는 어떤 지점에서 문제가 생겼는지 리포트를 통해 투명하게 확인할 수 있습니다.
* **API 호출 비용 최적화 (캐싱):** 로컬 파일 시스템(`os.path.exists`)을 활용한 캐싱을 적용했습니다. 동일한 날짜로 재실행 시, 무겁고 비용이 발생하는 LLM 및 지도 API 통신을 전면 생략하고 기저장된 원본 JSON 데이터를 즉시 로드하여 처리 속도를 극대화했습니다.
* **입력 정규화 (검색 품질 향상):** LLM이 "광역시/도"처럼 너무 넓은 범위를 추천하는 것을 막기 위해 프롬프트로 "시/군/구" 출력을 강제(사전 통제)하고, 지도 API 호출 시 `{city} 맛집` 형태로 검색 키워드를 강제 결합(사후 보정)하여 검색 정확도를 높였습니다.
